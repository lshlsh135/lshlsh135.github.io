🎯 한 줄 요약: 캐나다 앨버타 주정부가 Claude Code(Opus·Sonnet)로 4억 6,600만 줄의 정부 코드를 20시간 만에 점검하고 취약점을 수정한 사례입니다.

## 📌 무엇이 바뀌었나
- 앨버타 기술혁신부는 2025년부터 27개 주(州) 부처의 시스템(약 1,280개 애플리케이션, 3,400개 코드 저장소)을 Claude로 보안 점검해 왔습니다. 세금 기록, 조달 데이터, 사회복지 사건 파일 같은 민감 정보를 다루는 시스템입니다.
- 약 50개의 에이전트가 자율·병렬로 돌면서 보안 취약점, 인프라·배포 과정의 약점, 문서 공백을 스캔했습니다. 팀 추산으로 전통적 방식이었다면 약 6.5년 걸릴 작업을 20시간에 끝냈습니다.
- 기존 자동 스캔 도구가 놓쳤던 문제들도 찾아냈고, 앨버타는 다른 정부가 참고할 수 있도록 기술 백서 모음을 공개했습니다.

## 🛠️ 어떻게 쓰는가
Claude Code는 2단계 루틴으로 동작했습니다. 먼저 규칙 엔진(rules engine)으로 각 저장소에서 알려진 패턴을 표시(flag)하고, 그다음 그 표시들을 검토해 발견 항목마다 정확한 파일과 줄 번호를 인용해 개발자가 검증할 수 있게 했습니다. 취약점을 찾으면 Claude Code가 수정 코드를 생성·테스트·빌드했고, 자동 테스트가 없는 경우엔 테스트부터 작성했습니다. 코드가 너무 낡거나 복잡하면 더 현대적인 언어로 재작성했는데, 25년 전 Java로 손코딩해 최초 구축에 5개월 걸린 보조금 포털을 4~5일 만에 재구축한 사례도 있습니다.

지속적 보안 검토를 위해 Claude Agent SDK 기반의 전문 에이전트도 만들었습니다. 'red team' 에이전트가 공격자처럼 외부에서 애플리케이션을 탐색하고, 'blue team' 에이전트가 국제 보안 표준에 맞춰 방어를 평가하며 고칠 파일을 콕 집은 개선 계획을 씁니다. 매 검사마다 애플리케이션당 약 95개 보안 통제 항목을 점검합니다.

## 💼 누가 써야 하나
오래되고 문서화가 부실한 레거시 시스템과 수십억 달러 규모의 기술 부채를 안고 있는 주·연방 정부 기관, 대규모 코드베이스를 체계적으로 보안 점검해야 하는 공공 IT 조직에 참고가 됩니다.

## ⚠️ 주의사항
모든 패치는 배포 전에 부처 엔지니어가 검토·승인했습니다. 즉 AI가 자동으로 프로덕션에 밀어넣는 방식이 아니라 사람 검토를 전제로 한 워크플로입니다. 이 사례에 인용된 규모·시간(6.5년 대비 20시간 등)은 앨버타 팀의 자체 추산치라는 점도 감안하세요.
